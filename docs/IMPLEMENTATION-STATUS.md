## 今回の検証

- 25チェック成功。実際の音声セッションをミュート・解除し、Core Audio側のMute値まで確認。対象のないセッションが別のプロセスをミュートしないことも確認。テストで変更したミュート状態は最後に復元。
- WPFの履歴期間・短音フィルター、並べ替え保持、イベント追加・値更新、760×650での履歴表示を確認。
- Windowsへのホットキー登録に成功。WM_HOTKEYをテストウィンドウへ送ってポップアップ表示を確認し、無効化後はコールバックしないことを確認。人のキーボード操作を試した結果ではない。
- テストは専用DBを使用。通常の履歴・自動起動設定は変更していない。
- メイン画面を作成する前に小型ポップアップを表示・閉じ、その後メイン画面を開く経路も確認。
- ホットキー待ち受けにWPFウィンドウを作らないように変更。最終単体EXEの初期トレイ起動20秒計測は72.8MB、CPU 0.23%（マシン全体換算）。画面を開いた後もこの値になるという意味ではない。
- 最終EXEの画面表示中20秒計測は161.2MB、CPU 1.62%（マシン全体換算）。画像生成を含まないが、起動直後の処理と実際の音声活動を含む短時間計測。画面表示中の100MB目標は未達で、安定アイドル時CPUの長時間評価も残る。初回計測141.2MB/0.90%からの変動もあり、単一値を保証しない。
- 最終単体EXEの起動・監視停止・再開・終了は検証モードで成功（終了コード0）。結果は `features-packaged-final`、負荷計測は `features-tray-final` と `features-window-final`。
- 結果: `artifacts/review/features-tests.txt`、`features-ui-results.txt`。画面: `quick-window.png`、`minimum-window.png`。

ホットキーの実装は [Microsoft RegisterHotKey仕様](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-registerhotkey) に従い、繰り返し通知を抑制し、終了時に登録を解除しています。
