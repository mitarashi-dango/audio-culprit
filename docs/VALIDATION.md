# 検証記録 — 2026-09-08

環境: Windows 11 (10.0.26200), .NET SDK 10.0.303 / runtime 10.0.11, x64。
実機の出力: Realtek Digital Output。

## 通過した検証

- Phase 1: 実音のCore Audioセッションから自身のPIDとPeak 0.025を検出。
- 開始閾値未満では記録しない。
- 無音保持・末尾無音除外・500ms以内の結合・離れたイベントの分離。
- 10分分のサンプルを投入して1イベントを維持し、継続再生扱い。
- 通知候補を継続音より優先。無視ルールを候補に適用、パスを優先。
- SQLiteのupsert、再オープンで履歴・除外保持、7日保持、履歴削除時の除外保持。
- 古いチェックポイントが完了イベントを上書きしない。
- 本番監視サービスで0.25秒の実音を検出。
- 別プロセスと自身が同時に鳴らした音を両方取得。子プロセス終了後も名前を保持。
- 監視OFFでアクティブ状態をクリア。ONへ復帰し、サービスを正常終了。
- WPFの実際の描画をPNGとして検査。実音の発生元・秒前・履歴行が表示されることを確認。
- アプリ自身の正常終了経路でプロセスが残らないことを確認。

検証実行プログラムは通常13項目、`--integration` 付きで17項目。統合テストは小さなテスト音を再生します。

## 負荷

開発Releaseのトレイ常駐20秒計測: Working Set 約65MB、マシン全体に対する平均CPU約0.19%。
画面描画・PNG出力を伴う検証ではメモリ100MBを超えます。100MB未満はすべての環境・画面表示状態で保証するものではありません。短時間計測であり長期間の負荷試験ではありません。
配布版の計測JSONは `artifacts/final-verification` に保存します。

## 手動受け入れテスト

1. 起動し、トレイアイコンを確認。×で格納し、左クリックで戻す。
2. 音楽を5分再生し、別アプリの通知を鳴らす。通知が最上部、音楽が継続再生になり、両方の履歴が残ること。
3. 詳細から音楽アプリを無視し、以後候補に出ないこと。設定から解除できること。
4. 出力をヘッドホンへ切り替え、そこで鳴らした音の出力名が変わること。
5. 終了・再起動後に履歴が残ること。削除の確認で「いいえ」は保持、「はい」は削除すること。
6. 必要な場合だけ自動起動をONにしてログインし直す。OFFで登録が消えること。
7. トレイの終了でプロセスが消えること。
