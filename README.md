# AudioCulprit — 音の犯人

**PCから謎の音。どのアプリが鳴らした？**

突然の通知音や電子音。何も操作していないのに鳴る音。\
AudioCulpritは、そんな音の発生元を探すWindows用ツールです。

起動しておくだけで、いつ・どのアプリが音を出したかを記録。「今の音？」と思ったら、鳴り終わった後でも発生元の候補を確認できます。

## ダウンロード

**[最新版をダウンロード](https://github.com/mitarashi-dango/audio-culprit/releases/latest)**

Windows 10 / 11（64ビット）対応。

ZIPを展開し、フォルダ内の **`AudioCulprit.exe`** を起動してください。インストール・管理者権限・.NETの別途インストールは不要です。

表示言語は自動選択されます。Windowsの表示言語が日本語なら日本語、それ以外は英語です。

> EXEは未署名です。Windowsの設定によって、起動時に警告や実行制限が表示される場合があります。

## 使い方

1. **AudioCulpritを起動しておく**
2. **気になる音がしたら、`Ctrl + Alt + A` を押す**
3. **発生元の候補を確認する**

ショートカットが使用中の場合は、`Ctrl + Alt + F10` に切り替わります。使用するキーは設定画面で確認できます。

ウィンドウの **×** を押すとトレイに収納され、監視を続けます。完全に終了するには、トレイアイコンを右クリックして **「終了」** を選んでください。

## できること

| 機能 | 内容 |
|---|---|
| 今の音？ | 最近の音の発生元候補を表示 |
| 怪しい音 | 10秒未満の短い音を一覧表示 |
| 現在再生中 | 今も音を出しているアプリを表示 |
| 音声履歴 | 時刻・アプリ名・再生時間・出力デバイスを確認 |
| 絞り込み | 最近の音や短い音だけを表示 |
| 無視 | 指定したアプリを発生元候補から除外。履歴には残ります |
| ミュート | 見つけたアプリの現在の音声出力をミュート |

履歴をダブルクリックすると詳細を開けます。実行ファイルの場所や、Windowsの音量ミキサーを開く操作もできます。

設定からWindowsログイン時の自動起動を有効にできます。初期状態では無効です。

## 保存とプライバシー

**音声そのものは録音せず、マイクにもアクセスしません。**

保存するのは、音が鳴った時刻・長さ・音量のピーク・プロセス情報・出力デバイスなどです。履歴と設定は、このPCの次の場所に保存します。

```text
%LocalAppData%\AudioCulprit\
```

履歴は **7日間・最大10,000件** 保持し、設定から削除できます。EXEを置き換えても履歴・設定は引き継がれます。

更新確認ではGitHubへ通信しますが、音声・履歴・プロセス情報は送信しません。テレメトリやアカウント登録はありません。

## 検出できないこと

AudioCulpritが表示するのは、音声出力から分かる**発生元の候補**です。

- **起動前や監視停止中の音**は記録できません。
- **ブラウザのどのタブか、通知の内容は何か**までは分かりません。
- **Windowsのシステム音**は、原因のアプリや機器を特定できない場合があります。
- **ごく短い音・小さい音・一部の排他モードの音**は検出できない場合があります。

ミュートは、そのアプリの現在存在する音声出力に適用します。後から作られる音声出力を継続的にミュートする機能ではありません。

## 更新

新しい通常リリースを **1日1回自動確認** し、更新があればトレイから通知します。設定で自動確認を停止したり、手動確認したりできます。

更新するときは、新しいZIPをダウンロード・展開し、起動中のAudioCulpritをトレイから終了してから、新しいEXEを起動してください。

自動起動を有効にしていてEXEの場所を変えた場合は、新しいEXEの設定で自動起動を一度オフにし、再びオンにしてください。

## 不具合報告

[Issues](https://github.com/mitarashi-dango/audio-culprit/issues) に、次の情報を添えてお知らせください。

- AudioCulpritとWindowsのバージョン
- 使用している出力デバイス
- 発生したことと再現手順

履歴やスクリーンショットには、ユーザー名や実行ファイルのパスが含まれる場合があります。投稿前に内容をご確認ください。

## 開発

C# / .NET 10 / WPF。Windows Core Audioの再生セッションを監視しています。

ビルドにはWindowsと.NET 10 SDKが必要です。

```powershell
# ビルド
dotnet build AudioCulprit.slnx -c Release

# テスト
dotnet run --project tests/AudioCulprit.Tests

# 実際に音を再生する結合テスト
dotnet run --project tests/AudioCulprit.Tests -- --integration

# 配布ZIPを生成
./publish.ps1
```
