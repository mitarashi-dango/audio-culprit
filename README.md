# AudioCulprit v0.2 — 音の犯人

「今の音、誰が鳴らした？」に答える Windows 10 / 11 用の常駐アプリです。
C# / .NET 10 / WPF。Windows Core Audio の再生セッションのピークだけを読み取り、音声は録音しません。

## 起動

単体の `AudioCulprit.exe` をダブルクリックして起動してください。ZIP展開やインストール操作は不要です。win-x64 自己完結版なので .NET の別途インストールは不要です。管理者権限も不要です。

- 上部の緑色「● 監視中」／オレンジ色「■ 監視停止中」で現在の状態を確認できます。「■ 監視を停止」「▶ 監視を開始」で切り替えます。停止中も保存済み履歴は閲覧できます。
- **今の音？**: 新しく鳴り始めた発生元の候補を表示します。
- **怪しい音**: 10秒未満の短いイベントを表示します。
- **現在再生中**: 30秒以上を「継続再生」として区別します。
- 履歴をダブルクリックすると詳細・実行ファイルの場所・除外・ミュート・音量ミキサーを操作できます。
- ウィンドウの × はトレイに収納します。完全終了はトレイの右クリック → **終了**。
- トレイの左クリックで開き、右クリックで監視の切替・設定を操作できます。
- 自動起動は初期状態で OFF。設定画面から明示的に有効にした場合だけ、ユーザーの Run レジストリに登録します。
- `AudioCulprit.exe --tray` で画面を開かず常駐できます。二重起動は防止します。

## 保存・プライバシー

保存先: `%LocalAppData%\AudioCulprit\audio-culprit.db`

SQLite に開始・終了・時間・ピーク・プロセス情報・出力デバイス・除外ルールを保存します。音声、PCM、マイク、会話、ブラウザ内容は取得しません。アプリ実行時の外部通信・テレメトリ・アカウントはありません。

履歴は7日間、最大10,000件。完了時と継続再生の30秒チェックポイントで保存します。異常終了後の継続イベントは最後のチェックポイントまでを履歴として復元します。設定の「すべての履歴を削除」は確認後に実行し、除外ルールは残します。再生中のイベントは終了時に新たに記録されます。

## 検出の仕様と限界

- 全アクティブ再生デバイスを監視。デバイス通知と2秒ごとの再列挙で接続・切断に追従します。
- 50ms間隔、開始閾値 0.01、終了閾値 0.005、無音保持250ms、同一セッションの統合間隔500ms。
- 時間計測に単調時計を使い、末尾の無音待ち時間を再生時間に加算しません。
- 短いイベントも完了確定まで最大約500ms待ち、画面は1秒ごとに更新します。
- プロセス名・パスはセッション発見時に保持します。権限不足・終了済みプロセスは取得可能な情報だけを残します。
- System Sounds は OS のセッション判定に従い、それ以外を推測でシステム音に分類しません。
- 新規の短音を継続再生より優先します。同時に鳴った全セッションは履歴に残ります。
- ブラウザのタブやDiscord通知の種類までは判別できません。
- 50ms未満の音、閾値未満の音、排他モードなどCore Audioセッションにピークが出ない音は取り逃す可能性があります。セッションのピークは人間が実際に聞いた音を保証するものではありません。
- **Ctrl + Alt + A** で小型の「今の音？」を開けます。他のアプリで使用中なら **Ctrl + Alt + F10** に切り替わります。使用中のキーは設定とトレイメニューに表示します。設定で無効化できます。ポップアップは呼び出した時点の音を表示します。
- 詳細の「このアプリをミュート」「ミュート解除」は、同じ実行ファイルの現在存在する音声セッションに適用します。パス不明の場合は、その履歴と同じセッションだけを操作します。新規セッションへの継続適用は行いません。
- 履歴は全期間／過去30秒／1分／5分、および10秒未満の短音で絞り込めます。音があった時間で抽出し、犯人候補と記録自体は変えません。

## 開発

.NET 10 SDK と Windows が必要です。初回復元には NuGet 接続が必要ですが、配布アプリの利用にはネットワーク接続不要です。

```powershell
dotnet build AudioCulprit.slnx -c Release
dotnet run --project tests/AudioCulprit.Tests
# 実音を短く再生するCore Audio結合テスト
dotnet run --project tests/AudioCulprit.Tests -- --integration
# Phase 1 単独プローブ（短い音を再生）
dotnet run --project tools/AudioCulprit.Probe
# 自己完結配布版
./publish.ps1
```

構成:

- `src/AudioCulprit.Core`: Core Audio監視、時間判定、候補選択、SQLite。
- `src/AudioCulprit`: WPF画面、トレイ、設定、起動、検証モード。
- `tests/AudioCulprit.Tests`: 依存テストフレームワーク不要の検証実行プログラム。
- `tools/AudioCulprit.Probe`: 最初の実機検証。
- `docs/SPEC.md`: 提供された仕様書。
- `docs/VALIDATION.md`: 検証結果と未検証項目。

開発用 `--verify <絶対フォルダ>` は専用DBと画面PNG・計測JSONを指定フォルダへ出力し、約21秒後に終了します。`--tray --verify <絶対フォルダ>` はトレイ起動を20秒計測します。通常起動時には動きません。

長時間検証は `--verify <絶対フォルダ> --soak` で12分間、5秒ごとのCPU・ワーキングセット・プライベートメモリ・マネージドメモリ・ハンドル数を記録して終了します。`--short-measure` の追加で3分間、`--tray` の追加で画面を作らず測定します。音の発生は別途テストEXEの `--soak <同じフォルダ>` で610秒の連続音と300秒・600秒時点の別プロセス短音を再生します。音量は小さめですが実際に音が出ます。実行後、テストEXEの `--check-soak <同じフォルダ>` で製品の保存履歴を確認できます。通常のユーザー履歴とは別のフォルダを指定してください。
